# Offline bake plan: Audio2Face-3D → `ziggy-face-track` (NOT run)

**Goal:** a one-off run on a GPU machine that turns our *fixed* voice clips into small face tracks
(`public/face/{character}/{locale}/{clip}.face.json`). The browser plays them with `PrecomputedTrackAnimator`.
NVIDIA never runs in production. The web game works the same without the tracks, through the
`WebFallbackAnimator` that `createFaceAnimator` falls back to.

The owner must approve the bake before it starts. It uses a GPU machine once: the owner's PC with an RTX card, or a
rented instance for about an hour. That is a one-off cost and adds no running cost.

## 0. Rules for this bake

- **Only fixed, adult, synthetic clips.**
  - Santa's lines (`src/data/santa/lines.ts`, 59 keys × FR/EN, Gemini TTS clips already cached by the CDN).
  - The elves' scripted notes, if and when they have recorded clips.
  - Optionally Ziggy's dodo segments, for comparison only. Ziggy keeps the Rust engine's phoneme visemes.
- **Never** bake a clip containing a child's first name or any child audio. Name clips stay on the web fallback.
  The bake machine receives only our own TTS audio.
- **Emotion input:** only `joy`, `amazement` and `cheekiness`, from our manifest. Every other entry in A2F's
  emotion vector (anger, disgust, fear, grief, outofbreath, pain, sadness) is forced to **0**. Audio2Emotion is
  not used and is not downloaded.
- **Do not modify the models.** This keeps us inside the Open Model License guardrail clause. Do not commit
  models, TensorRT engines or WAVs.
- **Output only:** the tracks. `source.model` and `source.modelLicense = "NVIDIA Open Model License"` are written
  in every track, with a line in `THIRD_PARTY_LICENSES.md`: "Face tracks generated with NVIDIA Audio2Face-3D
  (model not distributed)".

## 1. Machine

- Ubuntu 22.04 (or Windows 11).
- An NVIDIA GPU with ≥ 8 GB VRAM: RTX 3060+ / T4 / L4 / A10.
- CUDA 12.9 (≥ 12.8, < 13), TensorRT 10.13+, Python 3.10, git-lfs, CMake, g++, ffmpeg, Node 22 (for the converter).

## 3. Clip manifest (produced in the repo, on any machine)

`research/nvidia/bake/clips.json` (to be generated by a small script that reads `SANTA_LINES`):

~~~json
[
  { "id": "santa/fr/open.hohoho", "character": "santa", "locale": "fr",
    "url": "https://ziggy-ai.fr/api/santa/voice?k=open.hohoho&l=fr&v=<VOICE_VERSION>",
    "emotion": { "joy": 0.8, "amazement": 0, "cheekiness": 0.2 },
    "keys": [[0, "laugh", 1], [1.4, "smile", 0.7]] }
]
~~~

- The URLs are CDN-cached, so downloading them costs nothing. Download each clip once, compute its `sha256` and
  store it in the manifest.
- `keys` are our own emotion keys for the track. They come from the call script (when Santa laughs or winks), not
  from Audio2Emotion.
- The manifest generator **refuses** any clip key that takes a name parameter.

## 4. Bake tool (`bake-a2f`, C++, derived from `sample-a2f-executor`)

1. For each manifest entry: `ffmpeg -i in.mp3 -ac 1 -ar 16000 -f f32le clip.f32` (16 kHz mono float).
2. Create the **blendshape executor**: the geometry executor plus `IBlendshapeSolver` from the model's
   `bs_skin_config_*.json` (52 poses). Use one identity for everyone, for example Claire for v3.0. Calibrate
   per character later through our `CHARACTER_PROFILES`, not through the model. Settings:
   - Explicit emotion vector: 10 floats in network_info order, with only indices of amazement/cheekiness/joy
     non-zero.
   - `fps = 30`.
   - Use the multi-track executor to bake N clips in parallel.
3. Write the 52 weights per frame to `out/{id}.csv` (header = ARKit names in SDK order: `eyeBlinkLeft … tongueOut`).
   Also write the jaw transform if the clip needs a separate jaw. Its rotation can replace `jawOpen` for Santa.

Pseudocode:

~~~cpp
for (auto& clip : manifest) {
  auto exec = makeBlendshapeExecutor(modelJson, identity, /*tracks*/1, /*fps*/30);
  exec.setEmotion(clip.emotionVector);          // negatives = 0
  exec.accumulateAudio(load_f32(clip.path));
  exec.closeAudio();
  exec.run([&](const BlendshapeFrame& f){ csv.writeRow(f.weights /*52*/); });
}
~~~

## 5. Convert to our format (`research/nvidia/bake/to-face-track.mjs`, Node 22, no dependency)

- Read each CSV and keep only the channels a plush face uses (about 2 KB per 5 s): `jawOpen, mouthClose,
  mouthFunnel, mouthPucker, mouthRollLower, mouthStretchLeft, mouthStretchRight, mouthPressLeft, mouthPressRight,
  mouthUpperUpLeft, mouthUpperUpRight, mouthSmileLeft, mouthSmileRight, eyeBlinkLeft, eyeBlinkRight, browInnerUp,
  cheekSquintLeft, cheekSquintRight`.
- **Drop** `mouthFrown*`, `browDown*` and `noseSneer*`. The validator refuses them anyway.
- Quantise to 8 bits, base64 frame-major, and write
  `{ format: "ziggy-face-track", version: 1, id, fps: 30, frames, duration, channels, data, emotions: keys,
  source: { generator: "audio2face-3d", model: "Audio2Face-3D-v3.0/Claire", modelLicense: "NVIDIA Open Model License",
  audioSha256, createdAt } }`. This is exactly what `encodeTrack()` in `src/lib/face/track.ts` produces; the script
  mirrors it.
- Write to `public/face/santa/{fr|en}/{key}.face.json`.

## 6. Verify (back in the repo, no GPU)

1. Add a `src/lib/face/tracks.test.ts` that runs `validateTrack()` on every `public/face/**/*.face.json` (format,
   limits, forbidden channels, emotion whitelist, `audioSha256` = hash of the current clip, so tracks go stale
   when the TTS text changes).
2. Compare with the web fallback on each clip: correlation of `jaw` and agreement of MM closures. Flag clips where
   A2F is not clearly better.
3. Run `/smoke` and Playwright video of Santa's call with and without tracks (1280×800, 390×844, and
   `reducedMotion: 'reduce'`). The owner decides from the side-by-side.
4. Bump `public/sw.js` `VERSION` when tracks are added or regenerated.
5. Run `npm run check` until it is green.

## 7. Loading at runtime (for whoever wires it)

~~~ts

const anim = createFaceAnimator(res?.ok ? await res.json() : undefined); // invalid/missing → web fallback
// each frame: scene.setTalk(toSantaTalk(anim.update({ dt, time: clipTime, spectrum })));
~~~
